# Content Schema

Documentation of every article frontmatter field in TubWise (`src/content.config.ts`), plus guidance for designing a niche-specific schema.

---

## Collection basics

| Item | Current behavior (TubWise) |
|------|----------------------------|
| Collection name | `articles` |
| Loader | `glob` on `./src/content/articles/**/*.{md,mdx}` |
| Config file | `src/content.config.ts` |
| Draft default | `draft: true` (safe unpublished default) |

---

## Category enum (niche-specific)

```ts
ARTICLE_CATEGORIES = [
  'troubleshooting',
  'water-care',
  'error-codes',
  'maintenance',
  'calculators',
  'buying-guides',
]
```

**Recommendation for a new site:** replace with `[CATEGORY]` values that match hubs and nav. Keep a closed enum. Do not keep hot-tub category names if they do not fit `[NICHE]`.

---

## Safety level enum (niche-specific)

```ts
SAFETY_LEVELS = [
  'none',
  'general',
  'chemical',
  'electrical',
  'professional',
]
```

Default: `'general'`.

Callout copy is generated by `safetyCopy()` in `src/utils/articles.ts` (**TubWise hot-tub wording — do not reuse verbatim**).

### Designing a future `safetyLevel` taxonomy

1. List real risk classes in `[NICHE]` (e.g. structural, medical, financial, legal, chemical, electrical).
2. Map each level to **UI behavior** (hide callout, show general caution, show hard stop).
3. Map each level to **editorial rules** (what DIY steps are allowed).
4. Keep the enum small (4–6 values). Prefer `professional` / `none` style clarity over vague `high`/`low`.
5. Never invent enum values in content commands — always read the live schema.

## Source object

| Field | Type | Required | Purpose |
|-------|------|----------|---------|
| `title` | string (min 1) | yes | Citation title |
| `url` | string | optional | Link when available |
| `publisher` | string | optional | Manufacturer / agency |
| `accessed` | string | optional | Access date |
| `note` | string | optional | Scope or claim note |

Rendered by `ArticleSources.astro`. Placeholder titles/notes block indexability.

---

## FAQ object

| Field | Type | Required |
|-------|------|----------|
| `question` | string (min 1) | yes |
| `answer` | string (min 1) | yes |

Array default `[]`. UI: `ArticleFaq.astro`. Placeholder Q/A filtered by `getValidFaq` / indexing helpers.

**Current behavior:** no `FAQPage` JSON-LD emitted. **Recommendation:** add only when FAQs are real and non-placeholder.

## Article fields

### `title`

| | |
|--|--|
| **Type** | `string` min 1 |
| **Required** | yes |
| **Purpose** | H1 and primary document title; also BlogPosting `headline` |
| **Generic example** | `"Why is my [DEVICE] making a clicking sound?"` |
| **Validation** | Zod min length |
| **Common mistakes** | Keyword stuffing; title ≠ H1 intent; brand-specific title without scoped body |

### `description`

| | |
|--|--|
| **Type** | `string` min 1 |
| **Required** | yes |
| **Purpose** | Meta description + OG/Twitter description + schema description |
| **Generic example** | `"Learn the common causes of clicking sounds and the safe checks to try before calling a technician."` |
| **Validation** | Zod min length; placeholder pattern excludes from index |
| **Common mistakes** | Duplicate across articles; marketing fluff; unresolved “TBD” |

### `summary`

| | |
|--|--|
| **Type** | `string` optional |
| **Required** | no |
| **Purpose** | Short answer shown near top of article; also search document field |
| **Generic example** | `"Clicking often comes from a relay or loose panel. Start with power-off visual checks."` |
| **Validation** | optional; placeholder pattern excludes from index |
| **Common mistakes** | Repeating the title; burying the answer |

### `slug`

| | |
|--|--|
| **Type** | lowercase kebab-case regex `^[a-z0-9]+(?:-[a-z0-9]+)*$` |
| **Required** | yes |
| **Purpose** | URL segment; `relatedArticles` key; search id |
| **Generic example** | `"why-is-my-device-clicking"` |
| **Validation** | Zod regex |
| **Common mistakes** | Uppercase; underscores; changing slug after publish without redirects |

### `category`

| | |
|--|--|
| **Type** | enum `ARTICLE_CATEGORIES` |
| **Required** | yes |
| **Purpose** | Hub membership and URL prefix for standard articles |
| **Generic example** | `"[CATEGORY]"` |
| **Validation** | enum only |
| **Common mistakes** | Inventing categories not in schema; mismatch with hub |

### `subcategory`

| | |
|--|--|
| **Type** | `string` optional |
| **Required** | no |
| **Purpose** | Hub grouping key (editorial convention) |
| **Generic example** | `"[SUBCATEGORY]"` e.g. `"heating"`, `"filters"` |
| **Validation** | free string today |
| **Common mistakes** | Inconsistent spellings that break hub groups |

### `brand` / `model` / `errorCode`

| | |
|--|--|
| **Type** | optional strings; `brand`/`errorCode` kebab-ish regex |
| **Required** | no (required in practice for TubWise error-code URL model) |
| **Purpose** | **TubWise niche:** specialized `/error-codes/{brand}/{errorCode}` routing |
| **Generic example** | Only if `[NICHE]` has product-code pages |
| **Validation** | regex when present |
| **Common mistakes** | Assuming one brand’s code meaning applies to another |

**Recommendation:** omit these fields from a starter schema unless the niche needs them.

### `publishedDate`

| | |
|--|--|
| **Type** | coerced `Date` |
| **Required** | yes |
| **Purpose** | Display date, sorting, BlogPosting `datePublished` |
| **Generic example** | `2026-08-01` |
| **Validation** | `z.coerce.date()` |
| **Common mistakes** | Future dates by accident; never updating when content changes materially |

### `updatedDate`

| | |
|--|--|
| **Type** | coerced `Date` optional |
| **Required** | no |
| **Purpose** | Shown when set; schema `dateModified` falls back to `publishedDate` |
| **Generic example** | `2026-09-15` |
| **Common mistakes** | Bumping date without substantive edits |

### `author`

| | |
|--|--|
| **Type** | `string` min 1 |
| **Required** | yes |
| **Purpose** | Byline; schema author Organization name in TubWise |
| **Generic example** | `"[SITE_NAME] Editorial Team"` |
| **Common mistakes** | Fake personal credentials |

### `reviewedBy`

| | |
|--|--|
| **Type** | `string` optional |
| **Required** | no |
| **Purpose** | Optional expert reviewer credit |
| **Common mistakes** | Naming a reviewer who did not review |

### `tags`

| | |
|--|--|
| **Type** | `string[]` default `[]` |
| **Purpose** | Search keywords; BlogPosting `keywords` when non-empty |
| **Generic example** | `["noise", "troubleshooting"]` |
| **Common mistakes** | Tag spam; tags that duplicate the entire site niche in every article |

### `featuredImage` / `featuredImageAlt`

| | |
|--|--|
| **Type** | optional strings; **alt required if image set** (`superRefine`) |
| **Purpose** | Article figure + OG/Twitter/BlogPosting image |
| **Generic example** | `"/images/articles/device-clicking.webp"` / descriptive alt |
| **Common mistakes** | Missing alt; reusing one image across many articles; localhost paths |

### `draft`

| | |
|--|--|
| **Type** | `boolean` default **`true`** |
| **Purpose** | Primary publication gate |
| **Common mistakes** | Forgetting to set `false` on publish; setting `false` before audit |

### `noindex`

| | |
|--|--|
| **Type** | `boolean` default `false` |
| **Purpose** | Robots/index gate; create/publish pipeline uses `true` while drafting |
| **Common mistakes** | Publishing with `noindex: true` left on; using noindex instead of fixing thin content long-term |

### `sources`

| | |
|--|--|
| **Type** | `sourceSchema[]` default `[]` |
| **Purpose** | Citations |
| **Common mistakes** | Empty on technical articles; placeholder titles; citing forums as primary |

### `relatedArticles`

| | |
|--|--|
| **Type** | `string[]` of **slugs** default `[]` |
| **Purpose** | Related module via `getRelatedArticles` |
| **Generic example** | `["related-slug-one", "related-slug-two"]` |
| **Common mistakes** | Using titles or paths instead of slugs; linking drafts; orphan related lists |

### `safetyLevel`

| | |
|--|--|
| **Type** | enum `SAFETY_LEVELS` default `'general'` |
| **Purpose** | Selects safety callout copy |
| **Common mistakes** | Inventing values like `"high"`; `none` on risky topics |

### `featured`

| | |
|--|--|
| **Type** | `boolean` default `false` |
| **Purpose** | Legacy/editorial flag; `getFeaturedArticles` prefers these |
| **Common mistakes** | Marking everything featured; confusing with `featuredImage` |

### `affiliateDisclosure`

| | |
|--|--|
| **Type** | `boolean` default `false` |
| **Purpose** | Shows `AffiliateDisclosure` on the article |
| **Common mistakes** | True without real affiliate relationships; missing sitewide disclosure page |

### `faq`

| | |
|--|--|
| **Type** | `{question, answer}[]` default `[]` |
| **Purpose** | Optional FAQ UI |
| **Common mistakes** | Keyword FAQ spam; placeholders; duplicating body verbatim without value |

## Generic vs TubWise-specific fields

| Generic (keep in starter) | TubWise-specific / optional |
|---------------------------|-----------------------------|
| title, description, summary | brand, model, errorCode |
| slug, category, subcategory | chemical/electrical safety labels (rename for niche) |
| dates, author, reviewedBy | hot-tub safety copy in `safetyCopy()` |
| tags, sources, relatedArticles, faq | error-code URL helpers |
| featuredImage + alt | |
| draft, noindex, featured, affiliateDisclosure | |
| safetyLevel **pattern** | safetyLevel **values and copy** |

## Indexability interaction

`isIndexableArticle` requires:

- `draft === false`
- `noindex === false`
- no placeholder content in body/description/summary/sources/faq

Schema validation alone does **not** publish an article.
